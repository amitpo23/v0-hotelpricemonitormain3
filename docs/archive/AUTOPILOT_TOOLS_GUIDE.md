## מה זה Autopilot Intelligence?

**Autopilot Intelligence** היא חבילת כלים מתקדמים לניתוח תמחור והכנסות, המשלבת:
- 🤖 **חיזוי מבוסס AI**: מה יקרה אם המערכת תנהל את התמחור אוטומטית?
- 🚨 **התראות חכמות**: זיהוי אוטומטי של תאריכים עם תמחור בעייתי
- 📊 **ניתוח מתקדם**: השוואה היסטורית, מתחרים, וביקושים

## חיזוי הכנסות Autopilot

### 🎯 מטרה
**לענות על השאלה:** *"כמה הכנסות אשיג אם אתן למערכת לנהל את התמחור אוטומטית?"*

### 📊 מה המערכת מנתחת?

1. **ניתוח היסטורי (YoY)**
   - השוואה לאותה תקופה אשתקד
   - זיהוי מגמות עונתיות
   - חישוב צמיחה שנתית

2. **ניתוח מתחרים**
   - איסוף מחירי מתחרים ליום
   - חישוב ממוצעים
   - זיהוי פערי תמחור

3. **ניתוח ביקושים**
   - תפוסה היסטורית
   - הזמנות מוקדמות
   - סופי שבוע vs ימי חול
   - אירועים מיוחדים

4. **המלצות Multi-Agent**
   - כל יום מקבל המלצת מחיר
   - רמת ביטחון (Confidence)
   - הסבר מפורט
   - הכנסות צפויות

### 📈 תוצאות שתקבל

#### כרטיסים סטטיסטיים
- **הכנסות נוכחיות**: מה תרוויח עם המחירים הנוכחיים
- **הכנסות עם Autopilot**: מה תרוויח אם תפעל לפי ההמלצות
- **עלייה**: כמה תרוויח יותר (₪ + אחוזים)
- **רמת סיכון**: low/medium/high

#### ניתוח היסטורי
```
אשתקד:        ₪150,000
השנה (חיזוי): ₪180,000
צמיחה YoY:    +20%
מגמה עונתית:  peak_season
```

#### הערכת סיכונים
המערכת מזהה סיכונים פוטנציאליים:
- ✅ **נמוך**: עלייה ממוצעת עד 30%, מגמה חיובית
- ⚠️ **בינוני**: עלייה 30-50%, יש לעקוב
- 🔴 **גבוה**: עלייה מעל 50%, סיכון לאובדן הזמנות

#### טבלת המלצות יומיות
```
תאריך          | מחיר נוכחי | מחיר מומלץ | הסבר
---------------|------------|-----------|------------------
15/1 (שישי)    | ₪450       | ₪520      | ביקוש גבוה (82%), סופ"ש
16/1 (שבת)     | ₪480       | ₪540      | תפוסה מלאה צפויה
17/1 (ראשון)   | ₪400       | ₪380      | ביקוש נמוך, יום חול
```

## מערכת התראות תמחור

### 🎯 מטרה
**לזהות ולהתריע על תאריכים עם תמחור בעייתי לפני שזה פוגע בהכנסות!**

### 🚨 5 סוגי התראות

#### 1. **Competitor Gap** (פער מתחרים)
```yaml
מה זה:     המחיר שלך שונה מאוד ממתחרים
קריטי:     הפרש מעל 35%
גבוה:      הפרש 25-35%
בינוני:    הפרש 20-25%
דוגמה:     אתה: ₪600, מתחרים: ₪420 (פער 43%)
המלצה:     הורד ל-₪450 להתאמה לשוק
```

#### 2. **Underpriced** (מחיר נמוך מדי)
```yaml
מה זה:     מחיר נמוך כשהביקוש גבוה
קריטי:     ביקוש >80% ומחיר נמוך ב-20%+
גבוה:      ביקוש >75% ומחיר נמוך ב-15%+
דוגמה:     תפוסה 85%, מחיר ₪350 (מתחרים ₪450)
המלצה:     העלה ל-₪420 לניצול מירבי
```

#### 3. **Demand Mismatch** (אי-התאמה לביקוש)
```yaml
מה זה:     המחיר לא מתאים לרמת הביקוש
דוגמה א:   תפוסה 90% אבל מחיר נמוך → העלה מחיר
דוגמה ב:   תפוסה 30% אבל מחיר גבוה → הורד מחיר
```

#### 4. **Anomaly** (אנומליה סטטיסטית)
```yaml
מה זה:     מחיר חריג מאוד (סטיית תקן >2.5)
דוגמה:     ממוצע ₪450, אתה ₪750
המלצה:     בדוק אם זו טעות הקלדה
```

#### 5. **Historical Deviation** (סטייה היסטורית)
```yaml
מה זה:     שינוי גדול לעומת אשתקד
נמוך:      סטייה מעל 30%
דוגמה:     אשתקד ₪400, השנה ₪550 (37.5%)
המלצה:     בדוק אם הסיבה מוצדקת
```

### 📊 לוח סיכום התראות

```
┌─────────────────────────────────────────┐
│  סה"כ התראות:     12                    │
│  קריטי:           3  🔴                 │
│  גבוה:            5  🟠                 │
│  בינוני:          4  🟡                 │
└─────────────────────────────────────────┘
```

### 💰 חישוב הפסד פוטנציאלי
כל התראה מציגה:
```
הפסד פוטנציאלי: ₪2,450
חישוב: (מחיר מומלץ - מחיר נוכחי) × מספר חדרים צפוי
```

## איך להשתמש?

### שלב 1: בחירת מלון
```
1. בחר מלון מהרשימה הנפתחת
2. תראה את מספר החדרים ומחיר הבסיס
3. המערכת תעדכן אוטומטית את הנתונים
```

### שלב 2: חיזוי הכנסות (Tab 1)

#### א. הגדרות
```
תקופת חיזוי: בחר 7/14/30/60/90 ימים
```

#### ב. לחץ "חשב חיזוי"
```
⏱️ הסורק יפעל 10-30 שניות
📊 יוצג ניתוח מפורט:
   - 4 כרטיסים סטטיסטיים
   - ניתוח היסטורי
   - הערכת סיכונים
   - טבלת המלצות יומיות
```

#### ג. פרשנות תוצאות
```
✅ עלייה 5-20%:   מומלץ מאוד ליישם
⚠️ עלייה 20-40%:  יש פוטנציאל, צריך מעקב
🔴 עלייה >40%:    בדוק טוב לפני יישום
```

### שלב 3: התראות תמחור (Tab 2)

#### א. הגדרות
```
תקופת בדיקה:     7/14/30/60 ימים
חומרה מינימלית:  קריטי/גבוה/בינוני/נמוך
```

#### ב. לחץ "סרוק התראות"
```
⏱️ הסריקה 5-15 שניות
🚨 תוצגנה התראות ממוינות לפי חומרה
```

#### ג. טיפול בהתראות
```
קריטי:   פעל מיד (תוך 24 שעות)
גבוה:    פעל בימים הקרובים
בינוני:  בדוק בשבוע הקרוב
נמוך:    לתשומת לב בלבד
```

## פענוח המדדים

### Confidence Score (רמת ביטחון)
```
90-100%:  ביטחון גבוה מאוד - המלצה חזקה
75-89%:   ביטחון גבוה - כדאי ליישם
60-74%:   ביטחון בינוני - שקול ליישם
<60%:     ביטחון נמוך - זהירות
```

### Demand Level (רמת ביקוש)
```
high:     תפוסה >75% או הזמנות רבות
medium:   תפוסה 50-75%
low:      תפוסה <50%
```

### Risk Level (רמת סיכון)
```
low:      שינוי מחיר ממוצע <30%, מגמה חיובית
medium:   שינוי מחיר 30-50%, דורש מעקב
high:     שינוי מחיר >50%, סיכון לביטולים
```

### Severity Levels (רמות חומרה)
```
critical: 🔴 דורש תשומת לב מיידית
high:     🟠 חשוב לטפל במהרה
medium:   🟡 מומלץ לטפל השבוע
low:      🔵 לידיעה בלבד
```

## דוגמאות שימוש

### תרחיש 1: תכנון תקציב רבעוני
```
מטרה: לראות אם כדאי להפעיל Autopilot ברבעון הבא

שלבים:
1. בחר מלון
2. Tab "חיזוי הכנסות"
3. תקופת חיזוי: 90 ימים
4. חשב חיזוי

תוצאה:
💡 הכנסות נוכחיות:  ₪450,000
🎯 עם Autopilot:      ₪540,000
📈 עלייה:             +₪90,000 (20%)
⚠️ סיכון:             בינוני

החלטה: כדאי להפעיל עם מעקב שבועי
```

### תרחיש 2: זיהוי בעיות דחופות
```
מטרה: למצוא תאריכים עם תמחור בעייתי

שלבים:
1. בחר מלון
2. Tab "התראות תמחור"
3. תקופת בדיקה: 30 ימים
4. חומרה: קריטי בלבד
5. סרוק התראות

תוצאות:
🔴 3 התראות קריטיות:
   - 22/1: מחיר גבוה מדי (40% מתחרים)
   - 28/1: ביקוש גבוה אבל מחיר נמוך
   - 5/2:  אנומליה - מחיר ₪850 (ממוצע ₪450)

פעולה: תקן את 3 התאריכים מיד
```

### תרחיש 3: השוואה שנתית
```
מטרה: להבין אם השנה טובה מאשתקד

שלבים:
1. חיזוי הכנסות → 30 ימים
2. חפש בקלף "ניתוח היסטורי"

תוצאה:
📅 אותה תקופה אשתקד: ₪120,000
📊 השנה (עם מחירים נוכחיים): ₪135,000
📈 צמיחה YoY: +12.5%
🎉 מגמה עונתית: peak_season

מסקנה: שנה טובה יותר, כדאי להמשיך באסטרטגיה
```

### תרחיש 4: בדיקה שבועית שגרתית
```
מטרה: בדיקת רוטינה שבועית

פרוטוקול:
1. כל יום ראשון בבוקר
2. Tab התראות → 14 ימים → בינוני ומעלה
3. סרוק התראות
4. טפל בהתראות קריטיות/גבוהות
5. תעד בספרדשיט

תבנית דיווח:
```
| תאריך בדיקה | קריטי | גבוה | בינוני | פעולות שבוצעו |
|-------------|-------|------|---------|----------------|
| 15/1/2025   | 2     | 5    | 3       | תוקן 22/1, 28/1 |
```
```

## 🔧 פתרון בעיות

### "אין נתונים מספיקים"
```
סיבה:     אין מספיק נתונים היסטוריים/תחרותיים
פתרון:    
- בדוק שיש חיבור ל-Apify
- ודא שיש נתונים ב-competitor_daily_prices
- בדוק שיש מחירים ב-price_predictions
```

### "החיזוי לא הגיוני"
```
סיבה:     אנומליה בנתונים או אירוע מיוחד
פתרון:
- בדוק את טבלת ההמלצות לפרטים
- חפש התראות Anomaly
- השווה למציאות (אירועים, חגים)
```

### "יש הרבה מדי התראות"
```
סיבה:     התמחור באמת בעייתי
פתרון:
- התחל מהתראות קריטיות בלבד
- טפל בהדרגה (5 תאריכים ביום)
- בדוק אם יש בעיה מערכתית (למשל: מחירון לא עודכן)
```
